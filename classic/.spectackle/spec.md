## EST-002 {applies: go:classic_test.TestPredictWidthGuardConsistency}
IF a predict-family method receives a row whose width differs from the feature count recorded at Fit, THEN the estimator SHALL return a clean error naming the row index, the got width and the want width, never panicking and never silently truncating.

Rationale: Two live failure modes: LinearRegression.Predict ranged over the input row instead of its coefficients, so a three-feature model given two features silently returned a plausible wrong number with a nil error; SVC panicked with an index-out-of-range while gradient boosting silently mispredicted, because shallow splits still traverse the surviving features. The guard lives at one site per estimator and is proven non-vacuous by stripping it and confirming the test goes red. Migrated from cavekit SPEC.md V37.

## MIRROR-A-GATHERED-COLUMN-FEATURE-MAJOR-001
WHEN a loop reads one column of a [][]T at a data-dependent row, x[idx[k]][f], and the same column is re-read many times, the owner of that matrix SHALL mirror it feature-major once where it is already walked and read the mirror, accepting the n*d element memory cost and gating the change with a bit-exact digest.

Rationale: Measured on the GBM exact-split builder. The gather x[cf[start+k]][f] was 51 percent of scanFeatures and 16 percent of the whole classic package: every read is a pointer chase into a separate length-d row, so n reads touch n cache lines spread over the whole n*d matrix and use 8 bytes of each. Feature-major turns the same access into a scattered read inside ONE contiguous length-n array. BenchmarkGBMHist_exact_80k minus 19.5 percent, _20k minus 13.6 percent, GBMFit minus 25.4 percent, with ForestFit flat as a control, for plus 15.6 percent bytes at n=20000 d=20 - exactly the n times d float64 the mirror costs, a trade to state rather than hide. The mirror is a pure copy so nothing moves by a bit, which is why only a bit-exact digest can gate it: two mutations that changed x by one ulp and that flipped the partition test from <= to < left every digest untouched, because the model reads x only through comparisons against midpoints of DISTINCT adjacent values and its outputs are leaf means of y. Four mutations do redden it. Encoded as perfscan PS3057, narrowed to the data-dependent row form: the strided x[i][f] shape has the same orientation but the rows are visited in order at a fixed stride, and including it reported 118 sites tree-wide instead of 3.
