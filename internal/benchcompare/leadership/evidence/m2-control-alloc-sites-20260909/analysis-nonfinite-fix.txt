T-01M241R5P3EH8 nonfinite exponent parser fix
================================================

Scope and outcome
-----------------

Independent verification found that pinned Ruby 2.6.10 converts overflowed JSON
exponent tokens such as 1e999 to nonfinite Float values despite allow_nan:false.
AllocationSites.parse now recursively checks the parsed root, Hash values, and
Array elements and raises AllocationSites::Invalid with the exact traversal path
for any nonfinite Float. Duplicate-key rejection is unchanged because JSON still
constructs every object through UniqueObject. Finite Float tokens remain parseable;
AllocationSites.analyze continues to reject them wherever the capture schema
requires an Integer.

Only the two already declared Ruby files were changed. The schema, prior evidence,
and original report.txt were not changed. No lifecycle or Git mutation occurred.

Fix applied
-----------

Used apply_patch to make only these bounded changes:

* analyze_sites.rb: retain the JSON.parse result, recursively traverse Float,
  Hash, and Array values, reject !finite? Float values with path and reason, and
  return the unchanged parsed object otherwise.
* analyze_sites_test.rb: add independent positive/negative root overflow probes,
  nested mixed Hash/Array overflow probes, finite root/nested exponent parsing,
  and proof that a finite exponent parsed as Float is still rejected downstream
  for the integer n field.

No finite value is converted or normalized by the new traversal.
