Blocking finding
================

AllocationSites.parse violates the explicit strict-JSON contract that parse itself
reject NaN/Infinity. On the required Ruby 2.6.10, JSON.parse with allow_nan:false
rejects literal NaN and Infinity tokens, but a syntactically valid, finite decimal
token with an overflowing exponent (for example 1e999) is converted to Float::INFINITY.
The implementation returns that value without recursively checking the parsed root,
arrays, or objects. The direct probe below observed Infinity at the root, -Infinity
in an array, and Infinity nested in an object. The independent supplemental test
therefore failed exactly as intended. This is a contract defect even though analyze
would later reject a Float used in an integer schema field, because parse is a public
entry point and its contract independently forbids non-finite values.

Required correction: after JSON.parse, recursively reject any Float for which
finite? is false at the root or at any array/object depth. Finite Float JSON values
may remain parseable; schema integer fields continue to reject every Float. No schema
relaxation is justified.

No fix was made in this verifier snapshot. The original failure and supplemental
test are preserved for a separately fixed fresh snapshot.
