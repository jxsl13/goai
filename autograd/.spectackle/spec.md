## PERF-TAPS-UNDER-A-CONTIGUOUS-OUTER-LOOP-001
IF an inner tap loop looks like it strides a large array, THEN the implementing agent SHALL confirm no enclosing loop advances that access contiguously, since K taps under a contiguous outer loop are K sequential streams rather than a stride.

Rationale: The conv1d VJP indexes xs and dxs at j*D+c with j varying by tap, which reads as a stride of D. It is not: the enclosing c loop advances all K positions contiguously, so the hardware sees K concurrent sequential streams. Interchanging k above c to make them contiguous measured p=0.505 at n=8 and was reverted; the kernel moves about 200MB per call and is memory-bound.

## SOFTMAX-SHIFT-NEEDS-A-RUNNING-MAX-001
IF a per-step softmax is collapsed to one precomputed exponential vector by factoring a constant offset out of its exponent, THEN the implementing agent SHALL keep the per-step maximum, because a fixed reference underflows the early terms to exactly zero and makes the denominator 0/0.

Rationale: In the RWKV WKV backward the exponent k_i minus (t-1-i)w rearranges to (k_i + i*w) minus (t-1)w, and the second term is constant across i, so it cancels in the softmax and the weights are proportional to one fixed vector exp(b_i) with b_i = k_i + i*w. Verified to 4e-16 max relative error against the existing loop. The algebra is right and the optimization is still unsafe: with the decay convention w > 0 the vector b spans about T*w, so at seq=512 with a per-channel w of order 2 the early entries underflow to exactly zero, and for small t every term of the denominator is one of those. The existing per-t maximum is load-bearing precisely because it pins the largest term at exp(0). An online running-max rescale repairs the denominator and numerator in O(1) each, but a gradient loop that needs every p_{t,i} individually must restate the stored vector at each new scale, which costs O(T) per growth and with monotone b is every step, returning the algorithm to quadratic. Removing the quadratic exp therefore requires the full reverse recurrence, where no individual weight is ever materialized, not this shortcut.

## A-SUM-LOSS-GRADCHECK-IS-BLIND-TO-UPSTREAM-WEIGHTS-001
IF a VJP gradcheck differentiates a plain sum of the outputs, THEN the implementing agent SHALL drive the VJP with a NON-UNIFORM upstream gradient before trusting it to validate a rewrite.

Rationale: Summing the outputs makes the upstream gradient identically one at every position, so every appearance of g_t in the VJP becomes a multiplication by one and any bug in how the upstream gradient weights the accumulation is invisible. Demonstrated on OpWKV by mutation: replacing dvcol[i] += gt*pi with dvcol[i] += pi is MISSED by the existing sum-loss gradcheck and CAUGHT by a sweep that uses a varied g. The same construction also hides t-index errors, because dv_i is a suffix sum over t and a permutation of a constant sums to the same value. Include exact zeros in g so any early-continue on a zero upstream gradient is executed, and sweep the shape together with the decay, since numerical behavior here is governed by seq times w rather than by either alone. A golden CHECKSUM test is not a substitute: it pins the current implementation bit for bit and must be regenerated by any rewrite, at which point it validates nothing about correctness and the gradcheck is the only remaining gate.

## DISTANCE-WEIGHTS-SPLIT-INTO-TWO-PREFIX-SUMS-001
IF a quadratic reduction is weighted by the DISTANCE between its two indices, THEN the implementing agent SHALL split the distance into its two indices, which turns one weighted sum into two ordinary prefix sums and makes the reduction linear.

Rationale: This is what unblocked the linear-time WKV backward, and it is the step that looks impossible until it is written down. dw is a sum over t and i<t of (t-1-i) times a weight, and a distance weight appears to couple the two indices so that neither can be accumulated independently. Writing (t-1-i) as (t-1) minus i separates them: the sum becomes (t-1) times S minus S1, where S accumulates the weights and S1 accumulates i times the weights, and both are ordinary prefix sums maintained in O(1) per step. The same split handles the value-weighted variant with N and N1. Every other gradient in that kernel was already a plain prefix or suffix sum; dw was the only one whose weight depended on the distance, and it was the only reason the whole pass looked irreducibly quadratic. Result: 10335 microseconds to 580 at seq=512, a 17.8x improvement, with the per-doubling ratio falling from 3.85 to 1.81.
