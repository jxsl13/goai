## PERMUTATION-BAND-TWO-GATES-001
WHEN a permutation nest is split into parallel bands, the its test suite SHALL gate it with BOTH a value comparison against the definition and a -race run, over at least 1 shape clearing the fan-out work gate.

Rationale: What makes a permutation safe to split is that every destination cell depends on nothing but its own source cell. That same property makes a band OVERLAP invisible to a value comparison: the intruding band writes exactly the value the owning band would have written, so the result stays correct and only the concurrent unsynchronized write remains. Measured on the transpose VJP, a mutation starting each band one tile early passed the value check and was caught only by -race. The converse also holds: a band that SKIPS rows, or one that reads the wrong source cell, produces wrong values with no concurrent access at all, so -race is silent and only the value comparison fails. Three such mutations were red on values and green on -race. Neither test subsumes the other. Two corollaries. Size every fixture above the work gate, or both arms run serially and no banding mistake can fail at all. And build the comparison so an unwritten cell is distinguishable: a fresh zeroed destination plus all-nonzero source values carries its own sentinel and needs no prefill. Folded into the PS3056 guidance so it reaches whoever applies the check.
