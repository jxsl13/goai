## TOK-003 {applies: go:nlp.BPETokenizer.EncodeSpecial}
The a control or special token SHALL be minted only from the specials-parsing path such as EncodeSpecial, never from untrusted text passed through plain Encode.

Rationale: This is a security property, not an ergonomic one: the chat template emits its markers as literal text, so untrusted content that could encode to the same control ids would forge conversation structure. Migrated from cavekit SPEC.md V30.

## TOK-004 {applies: go:nlp.BPETokenizer.EncodeSpecial}
The a new tokenizer or segmentation path SHALL close both the marker-matching pre-split and the segmentation search itself, and prove the gate by mutation testing that an always-parse design fails.

Rationale: Both paths have been live. GGUF stores control tokens inside the main vocabulary, so Unigram's Viterbi and WordPiece's MaxMatch search all of it and can mint a control token with no specials pass involved, which the Hugging Face analogy hides. The injection case is a required test. Migrated from cavekit SPEC.md V30.

## DEC-003 {applies: go:nlp.Llama.SelfExtendForward}
The a model architecture's per-block features such as biases, QK-norm and the Granite scalars SHALL be applied in one block stack that DecodeStep, StreamStep and SelfExtendForward all route through, with attention as the only pluggable part.

Rationale: Duplicated decode logic drifts silently and asymmetrically: streaming once dropped all six hooks while the normal path kept them, so the same model and prompt produced different tokens through different entry points with no error. Migrated from cavekit SPEC.md V31.

## DEC-004 {applies: go:nlp.Llama.SelfExtendForward}
IF a duplicated decode path must remain, THEN the package SHALL name it in godoc and pin it with a cross-path test comparing tokens, using nonzero feature values plus a feature-free control.

Rationale: Without the control, a failing gate cannot distinguish real drift from a broken harness. Comparing logits rather than tokens hides divergence that only shows after argmax. Migrated from cavekit SPEC.md V31.

## PERF-ROWSUM-UNROLL-001
IF a loop sums whole rows into one accumulator vector one row at a time, THEN the implementing agent SHALL sum 4 rows per pass with separate adds, cutting memory ops per element visit from 3 to 1.5.

Rationale: The shape is agg[j] += row[j] nested inside a loop over rows. It performs one add per element visit but three memory operations: load the input, load the accumulator, store the accumulator. Unrolling the ROW loop by U and emitting U separate adds keeps agg[j] in a register across the group and cuts that to 1+2/U, so 2.0 at U=2 and 1.5 at U=4, while every input row is still read contiguously. Bit-identical by construction rather than by tolerance: separate add statements in ascending row order preserve every term and its order, and pure adds involve no FMA contraction. Shipped in SnapKV aggregate: 137.5us to 110.3us, -21.08% at U=4 and -17.59% at U=2 on BenchmarkSnapKVKeep, 24 samples across both arm orders. The payoff does NOT depend on the accumulator fitting in cache — linalg QR gained on a 6 KB L1-resident accumulator and SnapKV on a 57 KB one; it depends on the loop share of runtime times the unroll factor the row count allows. Detected by perfscan PS1007.

## TEST-ORACLE-SHARES-THE-SUBJECT-001
IF a reference implementation kept in a test calls the same function it is meant to check, THEN the implementing agent SHALL replace the shared call with the 2 independent implementations, or the gate proves only that the code equals itself.

Rationale: A differential gate covers only what DIFFERS between its arms. Seen twice. In nlp, refSampleMirostat is a transcribed pre-optimization reference for Mirostat.Sample, but it calls sortIdxDescByProb itself, so any defect in that radix sort moves the reference and the implementation identically and the comparison stays green — the radix behind radixSortCutoff had no gate at all despite an oracle sitting right next to it. Earlier in linalg, TestOrthogonalBitIdenticalToSlowPath compared a fast path against a slow path where BOTH called applyReflector, so perturbing the shared reflector code moved both arms and the assertion held; that gap was closed with a frozen golden hash instead. The general shape: when writing a parity test, list what the two arms have in COMMON and confirm the code under test is not in that list.

## TEST-CANONICALIZER-NEEDS-ITS-OWN-GATE-001
IF a sort exists to canonicalize a key for a dedup or intern table, THEN the implementing agent SHALL assert permutation-invariance of the interned id directly, since 64 downstream tests missed a wrong comparator.

Rationale: GrammarGuide.internStacks sorts stack keys so that a stack SET interns to one state id regardless of arrival order. Converting that sort for PS6009 and TRANSCRIBING the old comparator instead of re-deriving it (sort.Slice passes positions, slices.SortFunc passes elements) compiles and sorts by a meaningless key — and the entire nlp package passed. It passes because a broken canonicalizer does not misparse: it costs deduplication, letting one stack set occupy several states, so the damage is a performance regression invisible to every correctness test. Assert the invariant itself: permutations of one input must intern to the same id AND must not grow the table. Two fixture traps, both hit before the test worked. The property is unobservable on small sets — with two elements the single comparison happens while the index permutation is still the identity, so correct and broken comparators agree — and a single fixed permutation such as a reversal can coincide by chance, so use many random shuffles over a set of at least three.

## DECODE-SCRATCH-BELONGS-TO-THE-STREAM-001
IF a per-token decode step allocates a short-lived buffer once per layer, THEN the implementing agent SHALL thread the buffer through the per-stream layer state rather than the shared mixer or model.

Rationale: A mixer holds weights and is read concurrently by every stream decoding against the same model, so scratch on it is a data race the tests will not reliably catch. A layer state is per stream and already advances one token at a time, which is exactly the lifetime the buffer needs. MEASURED on QuantMamba2 decode: rows2D materialized the in_proj output as [][]float64 once per layer per token and the caller kept row 0, which at seq=1 was 37 percent of all allocation objects in the step. Moving it to Mamba2LayerState went -18.37 percent B/op, -3.67 percent allocs/op and -0.54 percent sec/op across all seven quantization formats, p at most 0.01 in every cell. Two preconditions the compiler will not check: the element must be READ-ONLY at the call site, since the helper returned an independent copy and a reused buffer does not, and nothing may retain it past the step. Both held here by inspection. PS3012 finds the shape.

## AN-ALLOCATION-PATTERN-DOES-NOT-TRANSFER-001
IF an allocation fix that paid off in one model is proposed for a sibling model on the strength of the same code shape, THEN the implementing agent SHALL profile the sibling first, since the shape being present says nothing about its share.

Rationale: QuantMamba2 decode and Jamba decode both call rows2D once per layer per token to keep row 0. In QuantMamba2 that was 37 percent of allocation OBJECTS and removing it went -18.37 percent B/op. In Jamba the identical shape, at six call sites rather than two, is 1.21 percent — the step is dominated by matmulKernel at 50.45 percent because Jamba is unquantized and runs MoE experts, so its allocation profile is a different shape entirely. The six-site change was NOT made. The instrument had to be written before any of this was knowable: Jamba decode had no benchmark at all, and both rows2D regions were proved reached by temporary panics before the profile was trusted (BENCH-PROVE-THE-CODE-RAN-001). Same lesson as the 80x spread PS1005 records for the same transform within one package, now shown to hold across sibling models.

## A-BIT-EXACT-CONTRACT-BLOCKS-REASSOCIATION-ONLY-001
IF a kernel is set aside as blocked by a bit-exactness contract, THEN the implementing agent SHALL separate the transforms that change VALUES from the ones that only change how indices are proven, since the contract forbids the first and says nothing about the second.

Rationale: nlp randomOrthogonal was treated as closed for several rounds because TurboQuant regenerates its matrix at dequantization, so a changed draw would break every model quantized with the old one. That contract does forbid splitting its accumulators — the four-partial reassociation PS3010 reports there remains forbidden. It says nothing about bounds checks. Both Gram-Schmidt loops range one row while indexing another, and cutting the two rows to the same length is bit-identical by construction: same operands, same order, only the proof of range changes. TestRandomOrthogonalBitStable, which hashes the matrix, passes unchanged. Measured -3.17 percent at d=256 (p=0.002) and -2.47 percent at d=512 (p=0.000) on the hottest line in these lanes. The lesson is that blocked is a property of a TRANSFORM and not of a site, and recording a site as blocked without naming which transform hides the ones that are still available.
