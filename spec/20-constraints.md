| id | constraint |
| --- | --- |
| C1 | target Go 1.26. `CGO_ENABLED=0` = default build, ! green ∀ platforms. |
| C2 | cgo-LAST policy = measurable gate. Pure Go default (experimental `simd/archsimd` via `GOEXPERIMENT=simd` on AMD64; Plan9-NEON on ARM64; `avo`; goroutines). cgo/external-C only as optional build-tag backend when ALL hold: (1) Pure-Go version §V-green & optimized to ceiling (documented stages + roofline). (2) benchmark beats §C.thr vs that optimized Pure-Go version. (3) `CGO_ENABLED=0` stays fully functional (fallback everywhere). ⊥ all 3 → reject cgo, park idea in §B. |
| C3 | (thr): "deutlich" threshold = speedup ≥ 1.5× OR reaches ≥ 80% of C++ baseline that Pure-Go cannot. revisable → ADR. [B1] |
| C4 | dtypes f32 & f64 first; f16, bf16, int8 later. |
| C5 | tensor layout row-major + strides/views. |
| C6 | GPU → cgo unavoidable (no Pure-Go GPU path). GATING NUANCE (§R47, §T47): Metal needs NO build-tag — macOS system frameworks always present → guarded by `darwin && cgo` only, auto-included on native macOS builds (cgo = default). CUDA/Vulkan stay behind opt-in build-tags because libcublas/-lvulkan are build-time LINK deps not guaranteed present; runtime dlopen (libcuda.so/libvulkan.so.1) is the documented future path to make them tag-free too. All still cgo-gated → `CGO_ENABLED=0` pure-Go build unaffected (§V7). |
| C7 | NPU (ANE/CoreML, DirectML, oneDNN) = explicit non-goal of first stage. re-eval after GPU. ⊥ silent promise. |
| C8 | ⊥ commit ∨ push without explicit user permission. loop works in working-tree only. |
| C9 | deps minimal. Pure-Go path ⊥ pull cgo deps. accel backends isolate deps behind build-tags. |
| C10 | docs = first-class deliverable, ⊥ afterthought. ∀ public API → godoc for TWO audiences: AI professional (math/algorithm/paper-cite/§R) AND layperson (plain-language what/why/when). PLUS runnable godoc `Example`/`ExampleT_method` fns at MULTIPLE levels: (a) trivial (one call, minimal), (b) ≥1 realistic trivial use-cases, (c) ≥1 complex/EMBEDDED example showing the piece inside a bigger pipeline (e.g. LoRA inside a full fine-tune loop). examples ! compile & pass via `// Output:` (go test). guarded by V17. |
| C11 | ZERO-CONFIG accel = default UX. user does as little as possible to run on GPU/accel: cgo/build-tags are the ONLY gating (which backends compile in); at runtime each compiled-in backend self-detects (device present → Register in init) & the highest-preference registered one is auto-selected (§V18). user ⊥ required to write backend-selection code; MAY override order via backend.SetPreference or pick per-call via Context.WithBackend. no C toolchain / C libs → those cgo backends simply absent, pure-Go path still runs (§V7). NPU stays non-goal (§R45). |
| C12 | IDIOMATIC Go. ∀ public API → idiomatic Go conventions. [user feedback] |
| C13 | PUBLIC-API DOC GATE. SCOPE (user feedback 2026-07-13): applies to documentation with a HUMAN target audience — godoc, README, docs/*, runnable Examples; texts expected to be read by an LLM only (SPEC.md, FORMAT.md, LOOP.md, PLANNING_PROMPT.md) are EXPLICITLY EXCLUDED from the layperson rule (caveman/dense form stays). ∀ exported symbol in a PUBLIC pkg (non-internal, non-backend-impl) → godoc comment present (DUAL-AUDIENCE per C10 even for SIMPLE methods: professional + layperson); ∀ human-audience feature docs → where applicable BOTH a simple/easy example AND a complex/advanced one (C10's three-level ladder trivial/use-case/embedded already implements this — the gate keeps at least the per-type+per-method floor mechanical, the simple+complex pair stays a review criterion); ∀ exported STRUCT FIELD → own doc/inline comment (fields = public-facing API too; "docs for everything public facing" [user feedback]); ∀ user-facing pkg → ≥1 runnable Example; ∀ exported user-facing TYPE → shown in a runnable Example (its name, New`<Type>` ctor, or ExampleType); ∀ exported METHOD on a user-facing type → shown in a runnable Example too (method name invoked in any Example body, or a dedicated ExampleType_Method) [user feedback 2026-07-13: "a meaningful usage example for every type and every method, plus layperson and professional explanations, where necessary"] — even simple types/methods, "where meaningful" (types/methods where an example is not meaningful — interfaces, functional-option/callback func types, enums, config structs, fixture-heavy models, trivial accessors already exercised by their type's example — go on the justified typeExampleExempt / methodExampleExempt allowlists). ENFORCED mechanically by internal/apicheck (§V19), a test in the suite + `make apicheck`, part of `all`/`ci` → commit/push BLOCKED while red. backend impl subpkgs (ref/cpu/cuda/metal/vulkan/npu) + internal/* EXEMPT (registered via blank import, not user-called surface). turns C10/§V17 from convention into a hard gate. [user feedback] |
| C14 | TYPED OP PARAMS. op-parameter surface = idiomatic typed Go, ⊥ `map[string]any`. `backend.Attrs` = sealed interface, one typed struct per op w/ dual-audience field docs (§C13) + a `WithDefaults()` shared by kernel & VJP (defaults ⊥ drift). construction = compile-checked struct literal; a wrong field/type = compile error, ⊥ silent default. specialization of §C12 for the dispatch layer. | C15 | NO MAGIC STRINGS. identifier-like string literals (backend names, …) = TYPED constants/enums, ⊥ bare literals. backend.Name string-enum (backend.CPU/Ref/Metal/CUDA/Vulkan); Get/SetPreference/Register/Name() all typed. exception: a string literal that IS an enum's canonical value definition (backend/names.go) or an existing typed enum's Stringer (tensor.DeviceKind → tensor/device.go). enforced mechanically (§V21). | C16 | PUSH POLICY [user directive 2026-07-20 + 2026-07-21 "never wait, remove the waiting condition"]. Push each completed, VERIFIED unit IMMEDIATELY → PR → merge after green CI. | C18 | FURTHER READING MANDATORY [user directive 2026-07-13]. ∀ documentation of implementations, novel algorithms, methods (godoc pkg docs, docs/*.md, README feature sections) → wherever possible reference FURTHER READING the interested reader can use to go deeper: the defining paper (already required by C10/V16) PLUS surveys/books/canonical texts where they exist (e.g. Goodfellow et al. | C20 | ABBREVIATIONS ALWAYS EXPLAINED [user directive 2026-07-14]. ∀ human-audience documentation → every abbreviation/acronym is EXPANDED AND EXPLAINED at first use, preferably in layman terms (e.g. "GQA (grouped-query attention: several query heads share one key/value head, shrinking the cache)"; "GGUF (llama.cpp's single-file model format)"). | C21 | RESEARCH-GROUNDED DEFAULTS + KNOB DOCS [user directive 2026-07-14]. ∀ configuration knob (functional options, config struct fields, CLI flags, sampler/optimizer/tokenizer params): (1) DEFAULT VALUE ! grounded in /research wherever possible — the recommended value from literature/industry practice (papers, reference implementations: torch/llama.cpp/HF), so out-of-the-box behavior = best average performance/output, ⊥ fiddling required; (2) doc of every knob = DUAL AUDIENCE (layman + professional, per C10/C13) covering: what the knob does, behavior AT and NEAR its value boundaries (what degrades/saturates as you approach min/max), special values w/ special semantics explicitly documented (e.g. 0 = disabled, -1 = unbounded, nil = auto); (3) ALWAYS cite the research/reasoning behind the chosen default (§R row or external source; further-reading links per C18) — "why THIS default" is part of the doc, ⊥ bare numbers. audit of existing knobs vs C21 → new §T task. [user directive] |
| C22 | NEVER IDLE — HARD RULE [user directive 2026-07-14, EMPHATIC: "auf gar keinen fall ge-idlet werden darf"]. NO holding, NO idling, NO waiting-and-doing-nothing, EVER. Pushing is unrestricted (§C16): push each completed unit immediately, never wait. While blocked on CI / a wakeup → ALWAYS do productive work LOCALLY. DEFAULT work = PERFORMANCE OPTIMIZATIONS (beat the Python/C++/torch incumbents — §perf-gap, T620 conv rungs, and every measured A/B rung = one §T + docs/benchmarking.md row); else research/tests/docs/audits. If the main context is SATURATED → DELEGATE to worktree-isolated fresh-context SUBAGENTS (proven pattern §T620: vulkan fused conv +20%, measured A/B) — saturation is NEVER a reason to idle, it is a reason to delegate. "nothing safe/unblocked to do" is ⊥ a valid idle excuse: there is ALWAYS a perf rung to attempt+measure or a task to advance. A bare "hold and do nothing" wakeup with NO work performed = a C22 VIOLATION. Each LOOP fire while blocked MUST start or advance real work (own or delegated), not merely reschedule. [user directive] |
| C23 | CONFIGURABLE HETEROGENEOUS EXECUTION [user directive 2026-07-14]. backend assignment ! be PER-OP-PART configurable — different backends for different pieces of ONE operation (some layers/rows/tiles on GPU, others on CPU-SIMD) WHERE IT MAKES SENSE. The MECHANISM is REQUIRED (a config surface: per-op / per-layer backend override, composable with C11's zero-config auto-select). DEFAULT = the measured-best single backend; a per-op split on a device that FITS IN VRAM is a transfer≫compute LOSS (ADR-0008/ADR-0021/§C3), so the split is OFF by default and ENABLED only when (a) measured beneficial, or (b) forced by C24 (low-VRAM). ⊥ silently split — the routing is explicit + documented (C21 knob docs). [user directive] |
| C24 | LOW-END / LOW-VRAM FUNCTIONAL [user directive 2026-07-14]. GoAI ! run on low-end devices with LITTLE-TO-NO VRAM — SLOWER there, but FUNCTIONAL, NEVER a hard failure. NO hard VRAM floor. When a model exceeds device VRAM → transparently offload the overflow to CPU-SIMD (llama.cpp-style partial/layer offload — THIS is the legitimate use of C23's split: FUNCTIONALITY, not speed). CGO_ENABLED=0 pure-Go path stays fully functional everywhere (§V7/§C1). Graceful degradation, ⊥ crash / ⊥ OOM-abort when a fallback exists. [user directive] |
| C25 | GLOBAL-SCALE PERF MANDATE [user directive 2026-07-14, EMPHATIC: "IMMER bis auf das letzte prozent optimieren"]. GoAI is an AI library → at popularity it runs on MILLIONS-to-BILLIONS of devices, so EVERY 1% perf gain = a huge GLOBAL compute + energy saving. ALWAYS optimize to the LAST PERCENT on hot paths: DEVIRTUALIZE + INLINE maximally (dtype-switch-ONCE typed `[]T` kernels — ⊥ per-element interface dispatch / closure / Unravel-alloc, §base-perf-sweep), hoist invariants out of loops, zero allocation on the per-element/per-token path, measure every rung (§V22 A/B). "good enough" is ⊥ acceptable on a hot path; the roofline ceiling is the target. This is the WHY behind C22 (never idle → the idle default is perf): the global compute footprint. [user directive] |
| C26 | RECURSIVE DECOMPOSE → BOTTOM-UP VERIFIED ASSEMBLY [user directive 2026-07-15]. ∀ complex/hard task → recursively DECONSTRUCT into smaller subtasks, subtasks into sub-subtasks, until each LEAF is small enough to implement AND verify for correctness IN ISOLATION (unit test ∨ parity ∨ gradcheck ∨ collapse-test pins it @ tight tol). THEN assemble BOTTOM-UP: build each higher level ON the already-verified leaves. RATIONALE: a leaf verified in isolation eliminates bugs AT THAT LEVEL, ∴ a defect surfacing at a higher level is LOCALIZED to the NEW composition (verified leaves ruled out) → cheap fault-localization, only the higher-level integration test needs re-checking; a top-only-checkable big-bang hides an unbounded bug-search. Established stepwise-refinement ∨ divide-and-conquer ∨ modular-decomposition + test-pyramid discipline (§R247, §R248, §R249). ALREADY the repo's feature pattern: collapse-test pins base-equivalence @1e-10 → per-param gradcheck → e2e only checks integration (T654/T655/T660); the worktree-subagent split (C22) is decomposition at the task level. Composes with G3 (reference-first), G5 (parity=acceptance, proven≠claimed), C22 (decomposition ALWAYS yields a small next task → never idle), C25 (leaf-level verification protects hot-path micro-opts). ⊥ ship a composite whose correctness can only be asserted at the top. [user directive] |
| C27 | NEVER SKIP MARGINAL WINS [user directive 2026-07-21 '/spec never skip marginal wins' + 'measure and verify']. Every optimization that is MEASURED (§V22 best-of-N A/B, benchstat p<0.05) AND VERIFIED (bit-identical, non-vacuity-checked, package tests + any fuzz/golden green) ships IMMEDIATELY — its own commit/PR + a §Bench row via docgraph — regardless of magnitude; a real 1% is a win, not churn. The only bar is real+measured+correct, NOT size — no 'is it worth it / too small' deliberation. Distinct from §C3 (when an incumbent GAP is worth CHASING against a HW/BLAS ceiling): a win already in hand is never discarded for being small. But marginal ≠ unmeasured — every ship still REQUIRES the measure+verify gate. |
| C28 | ALWAYS START IDENTIFIED TASKS [user directive 2026-07-21 '/spec always start new identified tasks after finished previous tasks']. A CONCRETE, actionable task surfaced while working (a profiler hot-spot, a class-audit sibling, a flagged follow-up — has a file+target+definition-of-done) must be BOOKED as a §T row and then STARTED after the current task finishes, not left as prose 'queued for a future fire'. Chain: finish current → pick the next identified §T → start it (one task/fire, loop.md). If it is too large/risky for the remaining context, START it by DELEGATING to a fresh-context subagent (§C22) then reverify — delegation counts as starting; idle-queuing does not. Complements §C22 (never idle) + §C27 (never skip marginal wins). |
